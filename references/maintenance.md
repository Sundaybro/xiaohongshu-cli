# 功能分支维护

本分支在上游 CLI 基础上合入搜索过滤、楼中楼令牌、媒体下载、私信、创作者分析、视频发布，并增加用户搜索分页、当前账号关注列表、笔记历史及登录适配。实际命令以 `xhs --help` 为准；包版本可能仍为 0.6.4。

## 源码位置与安装

先确定当前设备的源码目录、分支、远端与工作树状态。不要把本机用户名、账号 ID 或 profile 路径固化进公开 skill。安装目录可用对应环境的 Python 查询 `xhs_cli.__file__`；读取位置不代表应直接修改安装产物。

主要源码：

- `client_mixins.py`：接口实现。
- `cli.py` / `commands/`：命令与参数。
- `client.py`：请求层和重试。
- `signing.py`：签名适配。
- `qr_login.py` / `cookies.py`：扫码及凭证管理。

修改源码并检查后，从源码目录安装：

```bash
uv tool install --force --reinstall-package xiaohongshu-cli .
xhs --help
```

直接改 site-packages 会在重装时丢失。本功能分支不宜用 `uv tool upgrade xiaohongshu-cli` 替换为 PyPI 包，否则可能覆盖扩展能力与 HERMES 补丁。

源码变更但包版本未变化时，uv 可能复用旧构建；显式重装该包，并从源码目录之外导入检查，确认实际安装文件包含新功能，避免只检查源码或帮助文本而误报更新完成。

## 更新分支

```bash
git status --short
git branch --show-current
git remote -v
```

确认用户的目标分支和上游远端后 fetch，审查差异，再合并正确的上游 ref。有本地提交的功能分支不能照搬主干的 fast-forward-only 更新流程。保留用户改动，不自动 reset 或强推。

维护 HERMES 补丁时，检查 `extract_browser_cookies()` 仍返回 None；不要通过实际解密浏览器凭证来验证。更换 Cookie 提取策略属于单独行为变更，不在普通升级里悄悄恢复。

## 验证范围

文档更新检查命令帮助、相对链接及 skill 格式即可，不运行真实账号写操作。代码更新根据变更运行单元检查和项目要求的静态检查。若沿用本分支测试，明确区分 `tests/test_integration.py`、`tests/test_smoke.py` 与隔离单元测试；真实接口测试另行授权和执行。

曾经的测试通过结果不能替代本次验证。私信与发布请求超时或服务端结果不明时，不增加自动重发来让检查变绿。

## 公开提交

公开代码、skill 与私有环境记录分开。提交前检查工作树和即将推送的提交范围，排除凭证、账号配置、浏览器 profile、二维码、下载内容和个人调研记录。

本地开发分支与公开脱敏快照可能有不同历史。推送公开更新时从已核实的公开分支建立提交，不为了发布文档而把私有开发历史一起合入。提交作者使用用户已选择的公开身份；不能把第三方贡献者原有信息误当作当前用户的隐私信息。
